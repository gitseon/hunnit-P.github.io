# PART 1. 객관식 100문항

## A. Post-training (Instruction-tuning · RLHF · DPO · RLVR)

### 1.
Pre-training과 Post-training의 역할을 가장 정확하게 구분한 것은?

① Pre-training은 사람이 원하는 방식으로 응답을 조정하는 단계이고, Post-training은 언어와 지식을 처음부터 새로 배우는 단계이다
② Pre-training은 방대한 텍스트로 언어와 지식을 배우는 단계이고, Post-training은 사람이 원하는 방식으로 대화하게 만드는 단계이다
③ Pre-training은 레이블된 지시문 데이터만 사용하는 단계이고, Post-training은 레이블 없는 원시 텍스트만 사용하는 단계이다
④ Pre-training은 추론 시 외부 저장소를 조회하는 단계이고, Post-training은 내부 파라미터만으로 답변을 만드는 단계이다

### 2.
Pre-training 단계의 대표적인 학습 목표로 옳은 것은?

① 사람이 매긴 응답 간 선호 순위를 맞추는 Preference Ranking
② 자동 채점기가 부여한 이진 보상을 최대화하는 Verifiable Reward
③ 앞선 토큰들을 보고 다음 토큰을 예측하는 Next Token Prediction
④ 질의와 문서 임베딩의 유사도를 높이는 Contrastive Learning

### 3. ★
"달 착륙을 6살 어린이에게 설명해줘"라는 요청에 Pre-trained LM이 답 대신 비슷한 형식의 다른 질문들을 이어서 생성한 이유로 가장 적절한 것은?

① 모델이 사용자의 의도를 수행하도록 학습된 것이 아니라 다음 토큰을 잘 예측하도록 학습되었기 때문이다
② 모델이 학습한 지식의 절대량이 부족해 달 착륙이라는 사건 자체를 전혀 알지 못했기 때문이다
③ 검색기가 관련 문서를 전혀 찾지 못해 참고할 수 있는 컨텍스트가 비어 있었기 때문이다
④ 보상 모델이 잘못된 점수를 부여해 학습된 정책이 붕괴하고 응답 품질이 무너졌기 때문이다

### 4.
문서에서 Post-training의 대표 기법으로 제시하지 않은 것은?

① Instruction-tuning: 지시문과 응답 쌍으로 지시를 따르도록 학습하는 방식
② RLHF: 사람의 선호 비교를 이용한 강화학습으로 모델을 정렬하는 방식
③ RLVR: 자동 검증이 가능한 보상을 이용해 정책을 갱신하는 학습 방식
④ Contrastive Learning: 긍정과 부정 문서 쌍으로 임베딩을 학습하는 방식

### 5.
Fine-tuning에 대한 설명으로 가장 적절한 것은?

① 레이블이 없는 대규모 텍스트에서 언어 패턴을 처음부터 학습해 나가는 과정이다
② 이미 사전 학습된 모델을 특정 작업이나 도메인에 맞게 추가로 학습시키는 과정이다
③ 사람이 비교한 선호 데이터를 이용해 보상 모델을 별도로 학습하는 과정이다
④ 추론 시점에 외부 데이터 저장소를 조회해 컨텍스트를 구성하는 과정이다

### 6.
Instruction-tuning의 정의로 가장 적절한 것은?

① 언어모델이 사람이 내린 지시문을 따르도록 학습하는 단계이다
② 보상 모델의 점수를 최대화하도록 정책을 갱신하는 단계이다
③ 모델 파라미터를 고정한 채 프롬프트만 바꾸어 성능을 올리는 기법이다
④ 문서를 청크로 나누어 벡터 저장소에 임베딩해 두는 단계이다

### 7. ★
일반적인 Fine-tuning과 Instruction-tuning의 차이로 가장 적절한 것은?

① 일반 Fine-tuning은 지시문 데이터만 사용하고 Instruction-tuning은 원시 텍스트만 사용한다
② 일반 Fine-tuning은 사람의 선호 비교를 사용하고 Instruction-tuning은 자동 검증 보상을 사용한다
③ 일반 Fine-tuning은 특정 Task에 맞춰 조정하고 Instruction-tuning은 다양한 Task를 수행하도록 학습한다
④ 일반 Fine-tuning은 사전학습 없이 처음부터 학습하고 Instruction-tuning은 반드시 사전학습을 전제로 한다

### 8.
문서에서 제시한 Instruction-tuning 데이터의 핵심 구조는?

① Query - Document - Score
② Instruction - Input - Output
③ Observation - Action - Reward
④ Host - Client - Server

### 9.
Super-NaturalInstructions 데이터셋의 규모로 옳은 것은?

① 약 52K개의 instruction-following 데이터로 구성된다
② 약 16,000개 이상의 실제 API로 구성된다
③ 약 6,000개의 인간 시연 데이터로 구성된다
④ 약 1.6K개 이상의 task와 3M개 이상의 예시로 구성된다

### 10.
Instruction-tuning으로 학습한 모델을 평가하는 방식으로 문서가 강조한 것은?

① 학습하지 않은 새로운 task에서 평가하여 지시 일반화 능력을 확인한다
② 학습에 사용한 task에서만 평가하여 수렴 여부를 확인한다
③ 사람이 두 응답을 비교해 선호 순위를 매기는 방식으로 평가한다
④ 자동 채점기가 정답 여부를 검증해 이진 점수를 매겨 평가한다

### 11.
MMLU에 대한 설명으로 옳은 것은?

① 16,000개 이상의 실제 API 호출 능력을 평가하는 벤치마크이다
② 웹 탐색 에이전트의 과제 성공률을 측정하는 시뮬레이션 환경이다
③ 57개의 지식을 요구하는 태스크에서 언어모델 성능을 평가하는 벤치마크이다
④ 검색기가 반환한 문서의 순위 품질을 측정하는 평가 지표이다

### 12.
K-MMLU의 특징으로 가장 적절한 것은?

① 기존 MMLU 문항을 한국어로 번역만 하여 그대로 사용하도록 만든 벤치마크이다
② 한국의 지식 환경에 맞게 구성되어 문화와 지역, 법률 등 한국 특화 지식을 요구한다
③ 수학과 코딩처럼 정답을 자동 검증할 수 있는 문제만 모아 구성한 벤치마크이다
④ 사람의 선호 순위를 대규모로 수집하기 위해 만들어진 응답 비교 데이터셋이다

### 13.
Alpaca에 대한 설명으로 옳은 것은?

① LLaMA 7B를 기반으로 약 52K개의 instruction-following 데이터로 학습한 모델이다
② GPT-3 175B를 기반으로 약 6,000개의 인간 시연 데이터로 학습시킨 웹 검색 특화 모델이다
③ 16,000개 이상의 실제 API를 활용해 도구 사용 능력을 학습시킨 대규모 언어모델이다
④ 1.6K개 이상의 task와 3M개 이상의 예시를 담은 지시문 데이터셋을 구축한 사례이다

### 14. ★
Alpaca의 학습 데이터 생성 방식으로 옳은 것은?

① 사람이 응답 두 개를 비교해 순위를 매기는 방식으로 선호 데이터를 대량 수집했다
② API 호출 후보를 샘플링해 실제로 실행한 뒤 손실로 유용성을 평가해 필터링했다
③ 질의와 문서를 하나로 결합해 Self-Attention으로 관련성을 계산하는 방식으로 모았다
④ 강력한 모델과 seed tasks를 이용해 Self-Instruct 방식으로 예시를 대량 생성했다

### 15. ★
Instruction-tuning의 한계로 문서에서 제시하지 않은 것은?

① 개방형이나 창의적 생성처럼 명확한 정답이 존재하지 않는 task가 있다
② 지도학습은 사소한 오류와 치명적인 오류를 동일하게 취급할 수 있다
③ 외부 저장소를 갱신할 수 없어 최신 정보를 반영하기 어렵다
④ 사람이 만든 답변이라도 항상 최적의 답변이라는 보장은 없다

### 16.
"언어모델이 모든 오류를 동일하게 취급한다"는 지적이 의미하는 바로 가장 적절한 것은?

① 정답 레이블이 전혀 없으면 학습 자체가 진행되지 않는다는 뜻이다
② 아주 사소한 오류와 치명적인 오류가 같은 loss로 처리될 수 있다는 뜻이다
③ 검색된 문서에 섞인 노이즈가 답변 품질을 떨어뜨린다는 뜻이다
④ 보상 모델의 점수와 실제 사람의 선호가 함께 증가해 간다는 뜻이다

### 17. ★
LM Objective와 Human Preference 사이에 차이가 생기는 이유로 가장 적절한 것은?

① 사람이 선호하는 답변은 정확성과 안전성을 포함하는데 토큰 확률만으로는 정의하기 어렵기 때문
② 언어모델이 외부 API를 호출할 수 없어 최신 정보를 전혀 얻지 못하는 구조이기 때문
③ 검색기와 생성기가 서로 다른 데이터로 학습되어 두 목표가 어긋나 버리기 때문
④ 데이터 계층과 전송 계층의 통신 규격이 호환되지 않아 충돌을 일으키기 때문

### 18.
Human-in-the-loop ML의 기본 흐름으로 옳은 것은?

① Query에서 Index를 거쳐 Retrieval과 Generation으로 답변을 만드는 흐름
② API 호출을 샘플링하고 실행한 뒤 필터링해 데이터셋을 만드는 흐름
③ Thought와 Action, Observation을 번갈아 반복하는 흐름
④ 사람이 레이블링하고 모델을 학습한 뒤 헷갈리는 데이터를 골라 다시 사람이 평가하는 흐름

### 19.
인간 선호를 반영한 최적화의 목표를 옳게 표현한 것은?

① 질의와 문서 임베딩 사이의 코사인 유사도를 최대화한다
② 모델이 생성하는 응답에 대한 기대 보상을 최대화한다
③ 클라이언트와 서버 사이의 메시지 왕복 횟수를 최소화한다
④ 검색된 문서 수를 늘려 컨텍스트 길이를 최대화한다

### 20.
RLHF의 정의로 가장 적절한 것은?

① 검증 가능한 자동 채점기로 보상을 계산해 정책을 갱신하는 방식
② 강화학습 단계를 제거하고 선호 데이터로 직접 최적화하는 방식
③ 인간의 피드백을 통해 사람이 선호하는 답변을 생성하도록 학습하는 방식
④ 지시문과 응답 쌍을 모아 다양한 태스크를 지도학습하는 방식

### 21. ★★
RLHF 파이프라인의 순서로 옳은 것은?

① SFT를 거쳐 비교 데이터를 수집하고 Reward Model을 학습한 뒤 강화학습으로 정책을 최적화한다
② Reward Model을 학습한 뒤 SFT를 하고 비교 데이터를 수집해 강화학습을 수행한다
③ 비교 데이터를 수집해 강화학습을 먼저 하고 SFT와 Reward Model 학습을 나중에 한다
④ SFT를 거쳐 강화학습을 먼저 하고 Reward Model 학습과 비교 데이터 수집을 나중에 한다

### 22. ★
RLHF에서 절대 점수 대신 응답 간 상대 비교를 사용하는 이유로 가장 적절한 것은?

① 상대 비교가 절대 점수보다 계산 비용이 훨씬 크기 때문
② 상대 비교를 쓰면 강화학습 단계를 완전히 제거할 수 있기 때문
③ 절대 점수로는 검색 결과의 순위를 매길 수 없기 때문
④ 인간의 절대 점수 평가는 일관성이 낮고 사람마다 기준이 달라지기 때문

### 23.
Reward Model 학습의 원리로 옳은 것은?

① 모든 응답에 절대 점수 레이블을 붙여 회귀 문제로 직접 맞춘다
② 사람이 더 선호한 응답의 보상이 그렇지 않은 응답의 보상보다 크도록 학습한다
③ 질의와 문서를 하나의 시퀀스로 결합해 Self-Attention으로 점수를 낸다
④ 정답이면 1, 아니면 0인 규칙 기반 이진 보상을 그대로 사용한다

### 24. ★
Reward Model 사용 시 주의점으로 문서가 지적한 내용은?

① 정확도는 오르지만 완벽하지 않으며 보상 모델이 잘못되면 강화학습도 잘못된 방향으로 간다
② 보상 모델은 항상 인간 평가 수준을 넘어서므로 별도의 검증 절차가 필요하지 않다
③ 보상 모델은 검색기 성능에 의존하므로 노이즈를 포함한 학습이 반드시 필요하다
④ 보상 모델은 공통 프로토콜 규격을 따라야 다른 모델에서도 재사용할 수 있다

### 25.
Reward Hacking에 대한 설명으로 가장 적절한 것은?

① 보상 모델의 점수와 실제 사람의 선호가 함께 꾸준히 증가해 가는 현상
② 검색된 문서에 노이즈가 섞여 최종 답변의 품질이 흔들리게 되는 현상
③ 실제 목표 달성 대신 보상 함수를 공략해 높은 점수를 얻으려 행동하는 현상
④ 모델의 사전지식과 주어진 컨텍스트가 서로 충돌해 답이 갈리게 되는 현상

### 26. ★
챗봇의 보상 구조가 낳을 수 있는 부작용으로 문서가 지적한 것은?

① 보상이 지나치게 낮아져 모델이 대부분의 질문에 대해 답변을 거부하게 된다
② 길고 자신감 있게 말하는 쪽으로 보상이 연결되어 Hallucination이 생긴다
③ 검색기가 관련 없는 문서를 우선 반환해 답변의 근거가 크게 흔들리게 된다
④ 툴 호출 스키마가 모델마다 달라져 같은 툴을 재사용하기 어려워지게 된다

### 27. ★
Reward Model Over-optimization 현상에 대한 설명으로 옳은 것은?

① 보상 모델의 점수와 실제 사람의 선호가 항상 비례해 함께 증가한다
② 보상 모델을 제거하더라도 강화학습 성능은 그대로 유지될 수 있다
③ 검증 가능한 보상을 사용하면 보상 모델 학습이 반드시 필요해진다
④ 보상 모델 점수는 계속 오르지만 실제 사람의 선호는 오히려 감소할 수 있다

### 28. ★
DPO의 핵심 아이디어로 옳은 것은?

① 강화학습 단계를 제거하고 선호 데이터로 언어모델을 직접 최적화한다
② 별도의 보상 모델을 반드시 명시적으로 학습한 뒤 정책을 갱신한다
③ 사람의 피드백을 전혀 쓰지 않고 모델이 스스로 데이터를 만든다
④ 자동 채점기로 계산한 검증 가능한 보상을 사용해 학습한다

### 29.
RLVR에 대한 설명으로 옳은 것은?

① 사람의 선호 비교 데이터로 보상 모델을 학습한 뒤 정책을 갱신하는 방식이다
② 정답이 존재하지 않는 개방형 창작 문제에 가장 적합하다고 알려진 방식이다
③ 정답 검증이 가능한 문제에서 Verifier로 보상을 계산하며 DeepSeek-R1이 사례다
④ 강화학습을 전혀 사용하지 않고 지도학습만으로 모델 정렬을 수행하는 방식이다

## B. Retrieval-Augmented LM (Information Retrieval · Retriever · RAG)

### 30.
Retrieval-Augmented LM의 정의로 가장 적절한 것은?

① 학습 단계에서 외부 문서를 파라미터에 통합해 저장하는 언어모델이다
② 추론 시 외부 데이터 저장소를 불러와 활용하는 언어모델이다
③ 내부 파라미터만 사용해 모든 답변을 생성하는 언어모델이다
④ 사람의 선호 비교로 보상 모델을 학습하는 언어모델이다

### 31.
Parametric Knowledge와 Non-parametric Knowledge의 구분으로 옳은 것은?

① Parametric은 모델 파라미터 내부의 지식이고 Non-parametric은 외부 저장소의 지식이다
② Parametric은 외부 저장소의 지식이고 Non-parametric은 파라미터 내부의 지식이다
③ 둘 다 모델 파라미터에 저장되며 갱신 주기와 압축 방식만 서로 다르다
④ 둘 다 외부 저장소에 저장되며 색인 구조와 검색 방식만 서로 다르다

### 32.
Datastore에 대한 설명으로 옳지 않은 것은?

① 가공되지 않은 대규모 텍스트 코퍼스일 수 있다
② 수억에서 수조 단위의 토큰으로 구성될 수도 있다
③ 위키피디아, 웹 문서, 기업 내부 문서 등이 해당할 수 있다
④ 반드시 라벨링되고 완전히 구조화된 데이터여야만 한다

### 33. ★
Query에 대한 설명으로 가장 적절한 것은?

① Query는 언제나 사용자의 질문 문장과 완전히 동일해야 한다
② Query는 반드시 벡터가 아닌 키워드 형태로만 표현되어야 한다
③ 언어모델의 최종 입력과 Query가 반드시 같을 필요는 없다
④ Query는 검색이 끝난 뒤 생성 단계에서만 만들어진다

### 34.
Index의 정의로 가장 적절한 것은?

① 문서나 단락처럼 검색 가능한 항목을 체계적으로 정리해 쉽게 찾도록 만든 구조
② 질의와 문서의 관련성을 사람이 직접 채점해 미리 만들어 둔 순위표이다
③ 검색된 문서를 요약해 언어모델 입력으로 넘겨주는 중간 처리 모듈이다
④ 모델 파라미터에 새로운 지식을 직접 써 넣어 갱신하는 편집 기법이다

### 35. ★
Information Retrieval에 대한 설명으로 옳지 않은 것은?

① 사용자의 질의에 맞는 정보를 대규모 데이터에서 찾아 제공하는 과정이다
② 주요 목표는 질의와 관련성이 가장 높은 정보를 제공하는 것이다
③ RAG는 이 개념을 활용해 검색된 문서로 더 정확한 답변을 생성한다
④ 언어모델이 내부 파라미터만 사용하여 정보를 생성하는 방식이다

### 36.
문서에서 제시한 Information Retrieval의 활용 분야로 옳은 것은?

① 모델 파라미터를 직접 수정하는 지식 편집에 활용된다
② 웹 및 아이템 검색, 추천 시스템, 검색증강생성에 활용된다
③ 강화학습의 보상 모델을 학습하는 데 활용된다
④ 툴 호출 스키마를 표준화하는 데 활용된다

### 37.
Retriever의 역할로 가장 적절한 것은?

① 검색된 문서를 바탕으로 최종 답변 문장을 만들어 내는 생성 모듈이다
② 사람의 선호 순위를 학습해 응답마다 점수를 매기는 평가 모듈이다
③ 질의에 맞는 후보 문서를 저장소에서 찾아오는 RAG의 첫 단계 모듈이다
④ 모델과 툴의 연결 규격을 통일해 주는 표준 프로토콜 계층이다

### 38.
Sparse Retriever와 Dense Retriever의 구분 기준으로 옳은 것은?

① Sparse는 어휘적 유사도, Dense는 의미적 유사도에 기반한다
② Sparse는 의미적 유사도, Dense는 어휘적 유사도에 기반한다
③ Sparse는 신경망 임베딩, Dense는 통계 가중치를 사용한다
④ Sparse는 재순위화 전용, Dense는 후보 검색 전용으로 쓰인다

### 39. ★
Sparse Retriever와 Dense Retriever의 대표 기법을 옳게 짝지은 것은?

① Sparse는 DPR과 Contriever이고 Dense는 TF-IDF와 BM25이다
② Sparse는 BERT 임베딩이고 Dense는 Inverted Index 구조이다
③ Sparse는 Cross-encoder이고 Dense는 Bi-encoder 구조이다
④ Sparse는 TF-IDF와 BM25이고 Dense는 DPR과 Contriever이다

### 40.
TF와 IDF의 의미를 옳게 설명한 것은?

① TF는 전체 코퍼스에서의 희귀도, IDF는 문서 내 등장 빈도를 뜻한다
② TF는 문서 내 등장 빈도, IDF는 전체 코퍼스에서의 희귀도를 뜻한다
③ TF와 IDF 모두 문서 내 등장 빈도를 다르게 정규화한 값을 뜻한다
④ TF와 IDF 모두 임베딩 벡터 사이의 코사인 유사도를 뜻한다

### 41. ★
this, is, and 같은 단어의 TF-IDF 가중치가 0에 가까워지는 이유는?

① 문서 내 등장 빈도가 낮아 TF 값이 0에 가까워지기 때문
② 임베딩 공간에서 다른 단어들과 거리가 매우 멀기 때문
③ 거의 모든 문서에 등장해 IDF가 낮아지고 가중치가 작아지기 때문
④ Inverted Index 구조에서 아예 색인되지 않기 때문

### 42. ★
TF-IDF 수식의 구성으로 옳은 것은?

① 문서 내 단어 빈도에 전체 문서 수를 그 단어가 등장한 문서 수로 나눈 값의 로그를 곱한다
② 문서 내 단어 빈도에 전체 문서 수를 그대로 곱한 다음 전체 값에 로그를 취한다
③ 단어가 등장한 문서 수를 전체 문서 수로 나눈 값에 로그를 취해 빈도에 더한다
④ 질의 임베딩과 문서 임베딩의 내적을 문서의 길이로 나누어 정규화한 값을 쓴다

### 43.
Sparse Retriever의 장점으로 옳은 것은?

① 동의어와 다양한 표현까지 의미 수준에서 처리할 수 있어 유연하다
② 복잡하고 긴 질의도 벡터 공간에서 풍부하게 표현할 수 있어 유리하다
③ 질의와 문서 토큰이 완전히 상호작용하므로 정확도가 매우 높은 편이다
④ 구현이 단순하고 Inverted Index로 빠르며 매칭 근거가 투명하다

### 44. ★
Sparse Retriever의 한계를 보여주는 사례로 가장 적절한 것은?

① 학습 데이터와 임베딩 모델의 품질에 검색 결과가 크게 좌우되는 문제이다
② bad guy와 villain처럼 의미는 비슷해도 단어가 달라 매칭에 실패하는 문제
③ 모든 질의와 문서 쌍을 개별로 계산해야 해서 검색 속도가 느려지는 문제이다
④ 검색 결과가 블랙박스처럼 동작해 이유를 설명하기 어려워지는 문제이다

### 45.
Bi-encoder의 구조로 옳은 것은?

① 질의와 문서를 하나의 시퀀스로 결합해 Transformer에 입력한다
② 모든 질의와 문서 쌍을 개별 계산하므로 대규모 검색에 부적합하다
③ 질의와 문서를 각각 독립적으로 인코딩해 임베딩 간 유사도로 관련성을 계산한다
④ 통계 기반 가중치로 단어의 중요도를 계산해 관련성을 매긴다

### 46.
Cross-encoder의 구조로 옳은 것은?

① 질의와 문서를 하나의 시퀀스로 결합해 모든 토큰이 Self-Attention으로 상호작용한다
② 질의와 문서를 각각 독립적으로 인코딩한 다음 코사인 유사도로 관련성을 계산한다
③ 문서 임베딩을 미리 계산해 두기 때문에 대규모 검색에서도 속도가 매우 빠르다
④ 단어의 정확한 일치 여부만을 기준으로 문서와 질의의 관련성을 판단하게 된다

### 47. ★
Bi-encoder와 Cross-encoder의 비교로 옳지 않은 것은?

① Bi-encoder는 문서 임베딩을 미리 계산할 수 있어 검색이 매우 빠르다
② Cross-encoder는 토큰 수준 상호작용이 가능해 정확도가 상대적으로 높다
③ Bi-encoder는 대규모 후보 검색에, Cross-encoder는 재순위화에 적합하다
④ Cross-encoder는 계산이 가벼워 전체 문서 집합 검색에 가장 적합하다

### 48.
Dense Retriever의 장점으로 옳은 것은?

① 매칭된 단어를 그대로 보여줄 수 있어 결과 해석이 매우 쉽다
② 동의어와 다양한 표현을 처리하고 복잡한 질의를 풍부하게 표현할 수 있다
③ 별도의 학습 없이 통계 계산만으로 즉시 사용할 수 있다
④ Inverted Index 구조 덕분에 검색 속도가 매우 빠르다

### 49. ★
Dense Retriever의 단점으로 옳은 것은?

① 표현이 다르면 매칭에 실패해 의미 수준의 이해가 제한되는 문제가 있다
② 질의와 문서가 결합되어 대규모 검색에는 아예 사용할 수 없는 문제가 있다
③ 연산 비용이 크고 블랙박스처럼 동작해 투명성이 낮으며 데이터에 의존한다
④ 사람이 만든 정답 레이블이 문서마다 반드시 필요하다는 문제가 있다

### 50. ★
RAG가 필요한 첫 번째 이유로 문서가 제시한 것은?

① 자주 등장하는 정보는 잘 기억하지만 희귀하거나 최신인 정보는 누락할 수 있다
② 희귀한 정보를 오히려 더 잘 기억하고 흔한 정보를 자주 놓치는 경향이 있다
③ 모든 지식을 파라미터에 완전히 저장할 수 있어 외부 검색이 불필요하다
④ 검색 결과가 주어지기만 하면 언제나 사실 정확성이 완전히 보장된다

### 51. ★
LLM의 지식 갱신과 관련해 RAG가 유리한 이유로 옳은 것은?

① 지식 편집 기법은 확장성이 뛰어나 외부 저장소보다 갱신이 훨씬 쉽다
② 외부 저장소는 한 번 만들면 수정이 어려워 결국 재학습이 필요해진다
③ 모델 파라미터는 검색 과정 없이도 실시간으로 자동 갱신될 수 있다
④ 지식 편집은 확장성이 부족한 반면 저장소는 쉽게 갱신해 최신 상태를 유지한다

### 52.
RAG가 필요한 이유 중 검증과 보안 측면에 해당하는 것은?

① 검색을 사용하기만 하면 답변의 사실 정확성이 언제나 보장된다
② 출처를 제시해 검증이 가능해지고 기업 내부 정보도 학습 없이 활용할 수 있다
③ 내부 문서를 모델 파라미터에 직접 학습시키는 것이 가장 안전하고 효율적이다
④ 출처 제시는 불가능하지만 최신 정보를 반영하는 것만은 가능해진다

### 53.
RAG 파이프라인의 순서로 옳은 것은?

① 문서를 먼저 검색한 다음 질문을 추출하고 마지막에 답변을 생성한다
② 답변을 먼저 생성한 다음 문서를 검색하고 마지막에 질문을 추출한다
③ 질문을 추출해 해석한 다음 문서를 검색하고 그 결과로 답변을 생성한다
④ 질문을 추출해 답변을 먼저 만들고 사후에 문서를 검색해 검증한다

### 54. ★
RAG의 첫 번째 과제인 Context 구성 문제에 대한 설명으로 옳은 것은?

① 필요한 정보를 어떻게 구성할지가 문제이며 컨텍스트 길이 확장이 해결 방향이다
② 검색 결과를 많이 넣을수록 성능이 좋아지므로 문서 개수만 늘리면 된다
③ 컨텍스트 길이는 고정값이라 늘릴 수 없으므로 검색 자체를 줄여야 한다
④ 컨텍스트 구성은 검색기 성능과 무관한 완전히 별개의 문제로 다뤄진다

### 55. ★★
검색 모델 성능 의존성에 대한 설명으로 가장 적절한 것은?

① 검색을 사용하면 컨텍스트에 있는 잘못된 정보도 모델이 쉽게 무시한다
② 검색 품질과 무관하게 RAG의 최종 결과 품질은 일정하게 유지된다
③ 노이즈는 생성 단계가 아니라 색인을 만드는 단계에서만 문제가 된다
④ 검색 모델 성능에 의존하므로 정보검색을 쓴다고 정확성이 보장되지 않는다

### 56. ★★
Noise Robustness와 Negative Rejection을 옳게 구분한 것은?

① Noise Robustness는 검색 문서에 정답 정보가 없을 때 추측하지 않고 거부하는 능력이다
② Noise Robustness는 노이즈가 있어도 정답을 찾고 Negative Rejection은 정보가 없으면 거부한다
③ 둘 다 사실과 반대되는 문서가 주어졌을 때 오류를 지적해 바로잡는 능력을 뜻한다
④ Negative Rejection은 여러 문서에 나뉘어 있는 정보를 통합해 답을 만드는 능력이다

### 57. ★
사전지식과 컨텍스트가 충돌할 때의 해결책으로 문서가 제시한 것은?

① 컨텍스트를 무시하고 모델의 사전지식을 항상 우선하도록 학습시킨다

③ 컨텍스트에만 근거해 답하도록 하고 정보가 없으면 거절하도록 학습시킨다
